<h2><a id="_5"></a>前言</h2> 
<p><font face="微软雅黑">我们开发过程中提到最多的就是版本控制&#xff0c;以前公司用的是svn&#xff0c;它比较适合开发人数不多的项目&#xff0c;属于集中式开发&#xff0c;而git是分布式版本控制系统&#xff0c;强调的是个体&#xff0c;可以有效高速处理从小到大的项目版本管理。GitHub是代码托管平台&#xff0c;类似这样的还有很多&#xff0c;例如码云等&#xff0c;本文主要讲解如何将Android Studio项目通过Git上传至GitHub以及在此过程中遇到的一些问题解决。在操作过程中需要GitHub账号、Android Studio项目和Git&#xff0c;下面是所用到软件的版本&#xff1a;Android Studio 4.&#43; 、Git 2.31.&#43; 。<br /> </font></p> 
<hr size="1&#34;" color="#000000" /> 
<h2><a id="Git__10"></a>一、Git 安装配置</h2> 
<p><font face="微软雅黑">1&#xff1a;Git安装 <a href="https://npm.taobao.org/mirrors/git-for-windows/" rel="nofollow">下载</a>。</font></p> 
<p>这是个git镜像下载地址&#xff0c;里面包含了很多版本&#xff0c;我们可以选择最近日期的版本。下载得到的是.exe文件&#xff0c;双击.exe&#xff0c;然后选项默认就好&#xff0c;一直next&#xff0c; 记录下安装路径&#xff0c;默认安装在C:\Program Files\Git&#xff0c;你也可以指定安装路径&#xff0c;装完成后可以右键点击桌面&#xff0c;点击Git bash&#xff0c;输入git --version查看版本&#xff0c;如下图&#xff1a; <br /> <img src="https://i-blog.csdnimg.cn/blog_migrate/105d7535c8a2ff80d9a1d99339ebd681.png" alt="在这里插入图片描述" /><br /> <font face="微软雅黑">我们安装完Git后需要创建全局用户&#xff0c;可使用 <strong>git config --list</strong> 验证当前本地属性&#xff0c;而<strong>git config --local --list</strong>查看的是当前仓库或Project下的git信息。下面是几个比较常用的命令&#xff1a;<br /> &#xff08;1&#xff09;修改当前的project的用户名的命令为&#xff1a;<strong>git config user.name target_username</strong><br /> &#xff08;2&#xff09;修改当前的project提交邮箱的命令为&#xff1a;<strong>git config user.email target_useremail</strong><br /> &#xff08;3&#xff09;如果需要修改全局下的用户名和用户邮箱&#xff0c;需要在上面的两条命令中添加一个参数&#xff0c;–global&#xff0c;代表的是全局。对应命令为&#xff1a;<br /> <strong>git config --global user.name target_username</strong><br /> <strong>git config --global user.name target_useremail</strong></font></p> 
<p>2&#xff1a;Git与Android Studio关联</p> 
<p>不得不说Android Studio对Git的支持还是很友好的&#xff0c;Git命令行基本操作都可以通过Studio来执行。</p> 
<p><strong>打开Android Studio<br /> 进入File–Setting–展开Version Control–Git<br /> 在Path to Git executable栏位输入安装Git的路径</strong><br /> 如下图&#xff1a;<br /> <img src="https://i-blog.csdnimg.cn/blog_migrate/f62370e9eddd5c09b7e45cb1dba21d6d.png" alt="在这里插入图片描述" /> <font face="微软雅黑">然后点击【Test】按钮&#xff0c;若出现Git的版本号&#xff0c;则说明配置成功&#xff0c;如下图&#xff1a;</font><br /> <img src="https://i-blog.csdnimg.cn/blog_migrate/19c5d7c8ef2f58129097b12e956263b1.png" alt="在这里插入图片描述" /><br /> 这时我们已将Studio与Git相关联。</p> 
<h2><a id="GitHub_35"></a>二、配置GitHub登录信息</h2> 
<p><font face="微软雅黑">还是在我们的Studio中&#xff0c;步骤&#xff1a;</font></p> 
<p><strong>进入File–Setting–展开Version Control–GitHub<br /> 点击面板的add account</strong></p> 
<p>出现如下图弹框&#xff1a;<br /> <img src="https://i-blog.csdnimg.cn/blog_migrate/1f8522d370df3f87cf46752d4af33fd0.png" alt="在这里插入图片描述" /></p> 
<p><font face="微软雅黑">这里输入你在GitHub上的账户密码&#xff0c;点击Log In&#xff0c;如果多次尝试依然链接不上github.com&#xff0c;可尝试右上角的Use Token方式登录</font><br /> <img src="https://i-blog.csdnimg.cn/blog_migrate/ab549f4c2a4777eb01909212dec552a2.png" alt="在这里插入图片描述" /><br /> 点击Use Token&#xff0c;如下图&#xff1a;<br /> <img src="https://i-blog.csdnimg.cn/blog_migrate/991a6d62bfbd69cafd9962501a9fef23.png" alt="在这里插入图片描述" /><br /> <font face="微软雅黑">这里我们需要注意的是Token栏和红箭头部分&#xff0c;这两个是我们能否进行登录成功的关键&#xff0c;我们登录自己的<a href="https://github.com/">GitHub</a>&#xff0c;然后打开Settings–Developer settings --Personal access tokens &#xff0c;如下图&#xff1a;</font><br /> <img src="https://i-blog.csdnimg.cn/blog_migrate/afc7a7757852c32bd554739f4324a318.png" alt="在这里插入图片描述" /><br /> 我们点击generate new token&#xff0c;出现如下界面&#xff1a;</p> 
<p><img src="https://i-blog.csdnimg.cn/blog_migrate/067da4fb0a63c08ad61cf2a74c5b88ca.png" alt="在这里插入图片描述" /><font face="微软雅黑">Note描述Token用处&#xff0c;关键在于我们需要勾选的部分&#xff0c;刚刚Studio使用Token登录界面下方有一串中括号[]框起来的字符&#xff0c;如&#xff1a;gist, read:org, repo&#xff0c;这里我们需要勾选这几项给这个Token,自己可以在上图的勾选框找这几个选项&#xff0c;然后点击Create Token生成Token&#xff0c;这时我们看到页面生成了一个Token&#xff0c;如下图&#xff1a;<br /> <img src="https://i-blog.csdnimg.cn/blog_migrate/edd45d735c4aefe07500995342f0667e.png" alt="在这里插入图片描述" />点击即可看到我们需要的Token值&#xff0c;这是一串字符&#xff0c;复制粘贴到我们的Studio里Token栏即可登录成功&#xff0c;面板上出现如下图GitHub账户信息&#xff1a;</font><br /> <img src="https://i-blog.csdnimg.cn/blog_migrate/120e673547e1b89f82a59f15efdcb930.png" alt="在这里插入图片描述" /></p> 
<h2><a id="GitHub_56"></a>三、上传项目到GitHub</h2> 
<p><font face="微软雅黑">进入VCS-&gt;Import into Version Control-&gt;Share Project on GitHub&#xff0c;如下图&#xff1a;</font><br /> <img src="https://i-blog.csdnimg.cn/blog_migrate/2f20178956440f0a2e407a6d9c6066ab.png" alt="在这里插入图片描述" /><br /> <font face="微软雅黑">第一次创建项目会出现如下弹框&#xff1a;<br /> <img src="https://i-blog.csdnimg.cn/blog_migrate/6e594b246351b175a40bb0cebdf56c84.png" alt="在这里插入图片描述" /><br /> 我们可以编辑仓库名、是否是私有库、描述该项目等信息&#xff0c;至于Remote&#xff0c;默认就好。然后点击Share&#xff0c;会出现如下图&#xff1a;</font><br /> <img src="https://i-blog.csdnimg.cn/blog_migrate/1396d553b2065b05df496f792d439157.png" alt="在这里插入图片描述" /><br /> <font face="微软雅黑">这个就是我们需要上传的项目&#xff0c;但是我们一般需要设置忽略文件&#xff0c;说明哪些文件可不必上传&#xff0c;因为一些文件只是idea编译或其它无关的文件&#xff0c;对项目运行没影响&#xff0c;下面是.gitignore文件的书写&#xff1a;</font></p> 
<pre><code class="prism language-java"><span class="token punctuation">.</span>gradle
<span class="token operator">/</span>local<span class="token punctuation">.</span>properties

<span class="token operator">/</span>captures
<span class="token operator">*</span><span class="token punctuation">.</span>iml
<span class="token punctuation">.</span>idea
<span class="token operator">*</span><span class="token punctuation">.</span>apk #optional
</code></pre> 
<p><font face="微软雅黑">当然你也可自己定义哪些文件忽略&#xff0c;具体可以上GitHub找几个大型开源项目&#xff0c;看看他们的.gitignore文件是怎样写的&#xff0c;有兴趣可以看看这个大神总结的&#xff1a;<a href="https://github.com/github/gitignore/blob/master/Android.gitignore">Android.gitignore</a>&#xff0c;上传成功后可登录自己的GitHub查看刚刚上传的项目&#xff0c;如下图&#xff1a;</font><br /> <img src="https://i-blog.csdnimg.cn/blog_migrate/1d8d63e249525cc4592f0db21a53fb19.png" alt="在这里插入图片描述" /><br /> <font face="微软雅黑">这里还有一点需要注意的是&#xff0c;Studio默认分支是master&#xff0c;而GitHub默认创建仓库主干是main&#xff0c;我们在上传项目时可以主动到GitHub上修改默认主干为master&#xff0c;如下图&#xff1a;</font><br /> <img src="https://i-blog.csdnimg.cn/blog_migrate/5ab617059c5b5a26d998c45939aec0d1.png" alt="在这里插入图片描述" /></p> 
<p><font face="微软雅黑">至此&#xff0c;项目就可比较完美地上传到GitHub仓库上&#xff0c;以后会出一篇项目开发中Android Studio 关于Git命令的使用&#xff01;</font></p>

				<div class="desc ellipsis-online ellipsis-online-1">### <em>Nginx</em> 文件名逻辑<em>漏洞</em>（CVE-<em>20</em><em>1</em>3-4547）

#### <em>漏洞</em>概述

<em>Nginx</em> 文件名逻辑<em>漏洞</em>（CVE-<em>20</em><em>1</em>3-4547）允许攻击者通过精心构造的 URL 请求来绕过<em>访问控制</em>并读取或执行受限资源。此<em>漏洞</em>的根本原因在于 <em>Nginx</em> 错误地解析了带有特定编码字符的 URL，从而导致文件路径处理不当[^<em>1</em>]。

#### 影响范围

该<em>漏洞</em>影响多个版本的 <em>Nginx</em>，在某些<em>配置</em>下可能导致未经授权的文件访问甚至远程代码执行。具体受影响的版本包括但不限于：

- <em>Nginx</em> <em>1</em><em>.</em>4<em>.</em>x 版本系列
- <em>Nginx</em> <em>1</em><em>.</em>5<em>.</em>x 版本系列 <em>(</em>部分)

当 Web 应用程序部署于上述版本之上时，可能存在潜在风险[^3]。

#### <em>复现</em>过程

为了验证这一<em>漏洞</em>的存在，可以通过上传一个看似无害但实际上<em>包含</em>恶意 PHP 代码的图片文件 `phpinfo<em>.</em>jpg` 来测试。一旦成功上传，攻击者能够修改 HTTP 请求中的参数使服务器错误解释文件扩展名，进而触发命令注入行为[^4]。

```bash
curl -X POST http://example<em>.</em>com/upload<em>.</em>php \
-F &quot;file=@/path/to/phpinfo<em>.</em>jpg&quot;
```

随后发送如下请求可尝试利用<em>漏洞</em>：

```http
GET /uploads/phpinfo<em>.</em>jpg%00<em>.</em>php?cmd=id HTTP/<em>1</em><em>.</em><em>1</em>
Host: example<em>.</em>com
```

如果存在<em>漏洞</em>，则返回的结果会显示当前用户的 ID 信息。

#### <em>安全</em>修复措施

针对 CVE-<em>20</em><em>1</em>3-4547 的防护手段主要包括以下几个方面：

- **升级至最新稳定版**：官方已发布更新解决此问题，建议立即应用最新的<em>安全</em>补丁以消除隐患[^2]。
  
- **手动修补源码**：对于无法即时升级的情况，可以从官方网站下载专门为此<em>漏洞</em>准备的<em>安全</em>补丁，并按照指引完成编译安装流程。

- **加强输入校验**：无论何时都应严格过滤用户提交的数据，特别是涉及文件操作的部分，防止非法字符进入内部处理环节。

- **启用 WAF 防护**：Web Application Firewall 能够识别异常模式并阻止可疑流量到达应用程序层面上游位置。

综上所述，及时采取适当行动可以有效降低遭受此类攻击的风险。</div>
